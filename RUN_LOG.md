## Edge seam + FPS (2026-06-13, from Lawrence's report: 13fps + square edge)
- Square edge: diagnosed by red-tinting the apron (no bleed-through → both sides are real water tiles, not bare apron). Root cause: the sim's edge-falloff ring + the scenery moat form a uniformly-deep FLAT band straddling the grid boundary, which outlines the diamond against the depth-mottled interior water. Fix: waterMottle() adds ±5% deterministic per-tile lightness jitter to ALL water (sim + scenery), so deep water is never a flat slab. Baked into cached tiles — zero per-frame cost. Seam gone.
- FPS: the world is rendered to a RenderTexture EVERY frame for the curvature mesh; on the user's dpr=2 display that RT was created at 2x = ~10 megapixels/frame, the dominant cost on WSL2's weak GPU. Fixes: RT resolution capped to 1 (4x less fill on hidpi), RT antialias off (no MSAA resolve on the per-frame pass), and guarded the per-frame biomeLayer/sceneryLand tint writes against cache thrash. (Headless renderer reads 54 regardless — it's a different bottleneck — so the user needs to report the real number.)
